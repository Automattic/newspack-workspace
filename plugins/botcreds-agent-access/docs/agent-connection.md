# Agent connection discovery (2.4.4)

The end-user setup guide and safe copy/paste prompt live in `readme.txt`, so WordPress.org can serve as the common setup reference. Agent Access supplies scoped application passwords, not an MCP transport or HTTP tools for a chat client.

## Contract

`GET /agent-access/v1/connection` (also HEAD) requires the **native verified managed BotCreds application password** of a readable WordPress account. It has no credential selector, mutation method or grant-editing capability. A browser login, unmanaged application password, spoofed MCP/audit header or Pro-token context cannot substitute. Anonymous access is 401; an authenticated but unsupported credential is 403. Credential selectors supplied in a query cannot change the principal or UUID.

Response schema 1 includes plugin version, publisher and REST URLs, authenticated user ID/login, configured scope and effective restrictive mode, selected additional grants, an allowlist of account capability booleans, dependency availability, approval status, configured content policy/rate ceilings, endpoint URLs and constraints. It returns no credential UUID, password, hash, email or list of other accounts. Scope metadata is the current request's UUID-specific configuration, not the first named password on an account.

`additional_permissions` reports selected configuration, **not unconditional operation availability**. Read-only takes precedence over SEO/full/selected writes. SEO scope routes writes exclusively to its dedicated API. Author assignment also requires CAP and already-editable content within scope. List users is a transient GET/HEAD-only grant on the native users route; use view context for full counts. Site management is a separate account-wide grant. Native capabilities and existing authority from other sources remain relevant.

Success and error responses from this route use `Cache-Control: private, no-store, max-age=0` and vary on Authorization/Cookie. Standard authentication bookkeeping, rate counters and existing legacy-scope migration still apply; this is a read-only API, not a claim of zero database side effects.

Copied connection JSON contains canonical `current_user_url` and `connection_info_url` generated by `rest_url()` rather than assuming root installation or pretty permalinks. Clients must not forward credentials on cross-host redirects.

## Verification

`tests/connection-http.py` and the private disposable fixture exercise actual HTTP authentication, two managed passwords on the same account, selectors, an unmanaged password, audit-header spoofing, authenticated administrator cookies, GET/HEAD, write denials, scope changes without password rotation, pending approval, revocation and stored-authority invariants. `tests/connection-wordpress.php` supplements these with synthetic native-UUID/Pro-context checks; these are explicitly not real Pro-token authentication coverage.

No Claude/Codex/GrokBot-specific connector configuration or compatibility certification is claimed. The shared HTTP reference client is tested; individual clients need their own acceptance checks.
