# Decisions

This is an append-only log. Notes about how the work was run were removed, and their numbers are not reused. Entries about the early exploration site (its pages such as `/shadcn`, `/plan` and `/seams`, its Astro endpoint) are history: that site is gone, and the package ships tokens, the shadcn theme and the registry only. There is no npm package; the shadcn registry is the only route.

1. **Astro 7.4.8.** The latest stable on the day. It needs Node 22.23.4 or later, so the repo pins Node 24.22.2 in `.node-version` and `engines` is left to Astro.
2. **Source path.** `scripts/tokens.mjs` reads `plugins/newspack-plugin/src/newspack-ui` by its repo-relative path, and resolves the `newspack-motion` import the SCSS makes to the sibling `packages/motion`. There are no environment overrides.
3. **Compile only `style.scss`, with Sass's JS API.** Plain `sass` with a custom importer for `newspack-motion`. No webpack.
4. **Fonts.** Copied to `dist/fonts` and the `?v=4.0` query stripped. Vite then hashes and emits them in the site build. No longer built: the package ships tokens only, and `scripts/tokens.mjs` copies no fonts (the `?v=` query is still stripped from the font URLs in the CSS).
5. **`:export` removed** from the CSS with PostCSS.
6. **JS: lazy `init()` over a thin entry.** The modules self-run on import, so `init()` loads them with a dynamic `import()`. `root` is accepted but unused. Output is one minified ESM file, no code splitting. No longer built: the package ships tokens only.
7. **Shims.** `wp.ajax.send` as a no-op, and `newspackUIData` passed through `init`'s second argument. jQuery is not shimmed because the one use is optional. No longer built, with the JS bundle.
8. **`tokens.json` shape.** Declarations on `:root` (including inside media queries), each with the raw `value` and a `resolved` value with `var()` references substituted. `color-mix()` results are not evaluated to hex, a later step can do that.
9. **Icons.** 17 icons extracted from the PHP file by a one-off script into `icons.ts`, whitespace collapsed. No longer built, with the JS bundle.
10. **Modal opening and snackbar triggers** are a 20-line site script using `data-modal-open` and `data-snackbar` attributes, since newspack-ui has no trigger of its own.
11. **Inline notices are not dismissible** in newspack-ui. The dismissible case on the page is the error snackbar, which carries a close button.
12. **Header nav** reuses newspack-ui's own scrolling tabs navigation (`newspack-ui__tabs--scroll`) rather than custom nav styles. A `site-nav` class only lets it shrink inside a flex row.
13. **Overlay click is not patched.** It does not close the modal in newspack-ui, and the POC does not add it.

## layout.css, as evidence for a layout layer

All values are newspack-ui tokens. It adds: page background and text color on `body`; a centered page width (`--newspack-ui-width-l`) with side gutters; a header with a bottom border; main and footer spacing; a prose measure (`--newspack-ui-width-content`) and vertical rhythm between prose children; section spacing and heading margins; a form max width; a focus outline for the skip link and header links; one rule so the scrolling nav can shrink. No component class is restyled.

Gaps in newspack-ui that this exposed: no page container, no section spacing scale for headings, no `body` baseline (margin, background), no prose rhythm for plain `p`/`h3`, and no focus style for plain links outside components.

## Newspack-shaped shadcn components

47. **`theme.css` now carries every newspack-ui token** (244 plus the 7 inside media queries, which are written as media blocks) with resolved values, next to the shadcn variables. `color-mix()` values stay as written, since browsers compute them. Components read tokens, so a token change reaches both sides.
48. **Components are hand-mapped, not generated.** Each registry file starts from the shadcn source (Radix primitives, props, `data-slot`s kept) and only class names and variants change. They set local custom properties (`--btn-bg`, `--nui-edge`) the way the SCSS does, so the state logic reads the same.
49. **Elevation comes from the real SCSS mixin.** `scripts/tokens.mjs` compiles the mixin at levels 1 to 4 into `build/newspack-ui/elevation.json`; the generator writes `--nui-elevation-1` to `4`. No offsets are copied by hand.
50. **Shared class strings live in a `registry:lib` item** (`lib/newspack-ui.ts`: focus layers and the field base) and the dialog and alert icons in another. Components depend on them by URL.
51. **Registry JSON is generated by our own script**, following the registry-item schema, not by `shadcn build`: it embeds file content, rewrites item names to absolute URLs (relative names would resolve to the official shadcn items) and writes the `newspack-ui` bundle. The host defaults to the live URL and can be set with `REGISTRY_BASE`.
52. **The site's `components/ui` and the two `lib` files are generated** from the registry sources by `install-ui` during `pnpm build` and are gitignored. Tailwind skips ignored files, so `shadcn.css` lists them with `@source`.
53. **Button variants**: default is primary (shadcn's default), plus secondary, outline, ghost, destructive, link. Sizes default, sm, xs and three icon sizes; `lg` is dropped since newspack-ui has none. Alert gets info, success, warning, error, with default and destructive kept as aliases. Badge gets muted, success and warning; ghost and link are dropped.
54. **Dialog is the medium modal by default**, as in the SCSS; the demo passes the small width. Below 600px it becomes a bottom sheet. The description sits outside the header in the demo, so it carries its own side padding.
55. **Radix behavior is left alone**, so two differences remain: overlay click closes the dialog and initial focus lands on the first button. Both are listed as gaps rather than patched.
56. **Dark hook**: `scripts/dark.mjs` holds token overrides and variable sources; a `dark` key in `tokens.json` is also read. Both are empty, so no `.dark` block is written.
57. **The shadcn scope** now takes font, size, line height and color from tokens and sets `-webkit-font-smoothing: antialiased`, which newspack-ui sets on `.newspack-ui` and which changed text weight visibly.
58. **Sonner not built.** The core components matched first; a toast needs the `sonner` package and snackbar stacking that newspack-ui does in JS. Superseded by 86 to 94, which add the `sonner` item.

## Change of direction: shadcn first

60. **The recommendation is now the shadcn registry, with the npm package deferred.** Later dropped for good: there is no npm package. The direction was decided upstream ("we don't want to own the JS"); the pages explain it with the evidence from `/shadcn` rather than reopen it. `/plan` leads with a decision table and an order-of-work table, and the `packages/ui` move is condensed under "If we ship the npm package later".
61. **Directory `packages/ui-shadcn`, package name `newspack-ui-shadcn`, private.** Unprefixed like the other directories, says what it is, keeps the POC package name, and leaves `packages/ui` free. It has no release config and is left out of releases.
62. **Default host: jsDelivr's GitHub endpoint pinned to the release tag.** The monorepo is public and multi-semantic-release already tags `<name>@<version>`. Checked: `cdn.jsdelivr.net/gh/Automattic/newspack-workspace@newspack-blocks@4.36.7/packages/icons/package.json` returns 200, so a tag with `@` resolves. Nothing to deploy, no secret, immutable URLs. Cost: the built JSON has to be in the tagged tree, so the release step generates it with the new version and commits it in the release commit, as the changelog is. A Space was not chosen as the default because it serves one build at a time (pinning would mean redeploying every old version) and needs a CI credential. Superseded: the registry is served from the product site, https://newspack-ui-theme.space.fast/.
63. **Dark values belong in newspack-ui's color SCSS**, under a selector newspack-plugin never sets, so tokens keep one source; `scripts/dark.mjs` is the stand-in. The generator's `.dark` block redefines the color tokens as well as shadcn's variables, because the components read the tokens directly.
64. **New gap: Inter.** `theme.css` names Inter but nothing in the registry loads it; on the POC it comes from newspack-ui's CSS. Listed on `/plan`, `/seams` and in `gaps.md`. Superseded by 71.

## Registry fixes from the first real install

71. **Fonts.** The theme item depends on `@fontsource-variable/inter` and imports it. Every family token and `--font-sans` use the stack `"Inter Variable", "Inter", ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif`. newspack-ui names its `@font-face` family `Inter` (`_fonts.scss`), so both names are kept: WordPress renders its own files, shadcn the fontsource ones, same face.
72. **Animations.** The theme item's `css` now carries `@import "tw-animate-css"` and the dependency. The CLI skips the import when the project already has it (as `init` does).
73. **`@theme inline` bloat.** The CLI generates a self-referential `--x: var(--x)` line for every non-color key in `cssVars`. Only the shadcn colors stay in `cssVars`; the 244 tokens, chart colors, elevation and media blocks go in `css` under `:root`, which also overwrites existing values (`cssVars` never does). The `--color-newspack-ui-*` utilities are dropped: no component uses them and `bg-(--newspack-ui-color-x)` reaches the same colors.
74. **Radius.** `rounded-xs` to `rounded-xl` map to border-radius-2xs, badge, control, surface and sheet. `rounded-2xl` to `4xl` are pinned to Tailwind's defaults so they do not drift. `--radius` is the surface radius and nothing derives from it, because `cssVars` carrying `--radius` makes the CLI re-derive the stock scale.

After `init`, the site must delete `--font-sans`, `--font-heading`, `--radius-*` and the Geist import, then install the theme item before the components. 76. **Base UI.** `init` defaults to Base UI, and the CLI then rewrites our Radix `asChild` to `render`, which fails type-checking. The docs say `init --base radix`.
77. **`--overwrite`.** Standard item names are kept. Documented that `--yes` alone stops at the overwrite prompt.
78. **Base URL.** `REGISTRY_BASE` already existed; it now also accepts a trailing `/r` or `/`, is written to `mapping.json`, and the `/shadcn` and `/plan` install commands read it.
79. **Icons use `fill="currentColor"`.** The dialog close icon was black on a dark surface. Found in dark mode.
80. **Validated** with `shadcn build` (schema passes) and installs into a fresh Vite, React and Tailwind 4 project, both after `init --base radix` and with only Tailwind and `components.json`: typecheck and build pass, Inter Variable loads, rounded-sm/md/lg compute 4, 8 and 12px, dialog enter and exit animations run, no console errors.

## Segmented Control

95. **`segmented-control` registry item**, new (shadcn has none). Built on Radix Toggle Group, `type="single"`, exported as `SegmentedControl` and `SegmentedControlItem` with `size="default" | "sm"`. Joins the `newspack-ui` bundle and `registry.json`. Depends on `radix-ui`.
96. **Never empty.** The wrapper drops the empty value Radix sends when the active item is pressed again, and owns the value when uncontrolled. Controlled use (`value`, `onValueChange`) works as in Radix.
97. **Arrow keys select.** Radix roving focus only moves focus; for a radio-like control the focused item is also the selected one, so an item that receives keyboard focus (`:focus-visible`) selects itself. Mouse focus is left to the click. Disabled items are skipped and focus wraps. Tab enters on the selected item only.
98. **Styles from the SCSS.** Track: neutral fill, surface radius, half spacer padding and gap. Item: ghost-button box (height spacer-8, 2.25 spacer padding, body size; `sm` is spacer-7, 1.75, small), medium weight, muted text, text color on hover and selected, inner segment radius. Selected: a surface thumb with a 1px outline inset shadow that slides in 200ms on the indicator curve (the `::before` pseudo-element on the track, moved with CSS variables). The first placement and resizes jump, as in newspack-ui; reduced motion removes the slide; forced colors hide the thumb and outline the selected item with `Highlight`. Focus is the 2px edge plus halo.
99. **When to use it versus Tabs.** A segmented control picks a value or switches the view of the same content: billing frequency, light or dark, list or grid. Exactly one is always selected. Tabs switch between different panels of content, with a panel under each tab. If the choice changes which content is shown, use Tabs; if it changes how the same thing is shown or which value is set, use a segmented control. Written in the item's `docs`, its description and a docblock on the component. shadcn has no equivalent (the Toggle Group is the closest primitive), so the registry has one.
100. **Checked** against newspack-ui's own on `/shadcn`, both sizes, light and dark: bounding box (320.2 by 48 and 272.9 by 44), padding, radius, font, weight, colors, thumb box, color, radius and outline, thumb transition duration and curve, hover color and focus edge equal. The one computed difference found (gap 8px against 6px at `sm`) was fixed. Installed from a local build into a clean Vite, React and Tailwind 4 app after `init --base radix`: typecheck and build pass. Keyboard (arrows, Home, End, Tab in and out, active item pressed twice), roles, 1280px and 320px and console errors checked with `playwright-cli`.

## Sheet, and no sheet handle

102. **The Dialog's bottom sheet has no handle.** newspack-ui draws a grabber bar on its bottom sheet because its sheet can be dragged down to close. Radix Dialog has no drag, so the bar promised a gesture that did nothing. The `::before` is gone, and below 600px the header's top padding is spacer-5, the same as the sheet's sides and bottom; the close button is centered on the title line at that padding.

A catch-all `button` and `[tabindex]` rule in the base layer was tried and dropped: it changed the offset, halo and radius of the registry Button, the search close button and the code block scroller, which already have their own rings. A keyboard walk of the docs, the search overlay and both drawers, at 1280, 1024 and 375, found no other focusable element without one.
151. **The wordmark can hold an island: `wordmarkLink`.** The wordmark sat inside the home link, so an interactive island there was a link inside a link (invalid), a click on its button followed the link home, and the link's `aria-label` hid it from screen readers. `SiteHeader`, `DocsSiteHeader`, `DocsShell`, `AstroDocs` and `AstroDocsSiteHeader` take `wordmarkLink` (default `true`, so nothing changes). Without a `wordmark` the site name always keeps its home link. With `false` and a `wordmark` the wordmark is a plain flex row with the same type styles and no link, and the island brings its own link home. Checked with a React island holding a link and a counter button in the `wordmark` slot: it hydrates, the button counts without leaving the page, and with the default the same button navigates away.
152. **The `newspack-ui` class on `body` has no rule and is gone from the guide.** Nothing in the kit styles `.newspack-ui`: the theme sets tokens on `:root` and `.dark`, and the page background and text color come from shadcn's `body` base style (`bg-background text-foreground`), which `shadcn init` adds. The old toggle (85) set `data-color-scheme` on `.newspack-ui` elements; the kit's toggle sets `.dark` on `html`. The Build a site guide no longer tells a site to add the class, and its Astro and Next.js layouts use a plain `body`.
153. **`"use client"` follows shadcn's rule.** A file gets it when it uses hooks, state, effects, event handlers or Radix primitives that need a client boundary; pure presentational files and the `lib` files do not. `label`, `dialog` and `sheet` were missing it (Radix Label and Dialog, as in shadcn's own copies). `button` and `badge` use only Radix `Slot`, and `card`, `alert`, `input`, `textarea`, `sonner` (which wraps a library that is already a client component and uses no hooks), `site-footer`, `drawer-nav`, `skip-link`, `mdx`, `astro-docs` and the `lib` files keep none, as in shadcn.

## Brand theme

154. **The brand theme is built after Neutral, from one override module.** `scripts/build-brand.mjs` runs as the last build step. It deep-copies the compiled Neutral item and applies the overrides in `scripts/brand.mjs`, the one place the brand lives. Neutral's outputs are not regenerated by it: apart from added files, added index and mapping entries and decision 156's link token, `dist/` has only Neutral's own content. A test confirms the brand step never rewrites `newspack-ui-neutral.json`; the comparison against a pre-brand baseline is opt-in (`NEUTRAL_BASELINE`) and compares that item's JSON. The step writes `dist/brand.css`, `registry/newspack-brand.json`, `registry/newspack-brand-fonts.json` and the `brand` section of `mapping.json`. Overrides land in both `cssVars.light` and `css[':root']`, since a mismatch would install different values than `brand.css` has. The two themes are alternatives: a site installs one.
155. **Light only, and the custom dark variant stays.** The brand item drops every `.dark` rule and `cssVars.dark`, including `.dark` selectors inside media blocks. It keeps `@custom-variant dark (&:where(.dark, .dark *))`. Without it Tailwind's default `dark:` variant follows `prefers-color-scheme`, and the components' `dark:` classes would switch on for anyone whose system is dark. Brand sites set `DARK_MODE = false`, so `.dark` is never set and those classes never apply. `brand.css` starts with the same line, so a site that imports the file directly gets it too; a test checks it.
156. **The link reads a token, and Neutral sets it to the text color.** The Button link variant reads `--newspack-ui-color-link`, with `--newspack-ui-color-text` as the fallback, so a site that updates the button before its theme still renders links in the text color. Neutral sets the token to `var(--newspack-ui-color-text)` and the brand points it at Cobalt. This is the one allowed change to Neutral's output: `button.json`, `newspack-ui-neutral.json` and `theme.css` differ only by that token.
157. **Cobalt has named roles, and `brand` renders like the default.** Cobalt (primary-600, `#003DA5`) is the default Button fill (the `--newspack-ui-color-btn*` tokens the components read, with `--primary` and the sidebar mirrors), links, the focus ring and its halo, checked Checkbox and Radio, the active Tab marker, and h1 and `font-display` text. Anchors with no class attribute and no `data-card` attribute get the link color and an underline too (`a:where(:not([class], [data-card]))`). The `a` stays outside `:where()` because Tailwind preflight's `a { color: inherit }` sits in the same base layer at (0,0,1) and would beat a zero-specificity rule; brand.css loads after it, so the rule wins by order. Any classed anchor or utility still wins, and the docs heading self-links (`data-card`) stay unstyled. Button hover and pressed reuse the existing recipe, the fill mixed 85% and 75% toward the surface in oklab. Text, muted text, borders, the Secondary, Outline and Ghost buttons, the Segmented Control thumb and inputs keep Neutral's values, and buttons keep Neutral's 8px radius. `variant="brand"` keeps its components and Neutral values, and in the brand theme it renders the same as the default Button, so pages that use it keep working. `--chart-1` to `--chart-5` are Cobalt, Emerald, Morganite, Amber and a Cobalt tint (`#6086c7`); status colors stay Neutral's. Accent fills for Emerald, Morganite and Amber ship with their tints and an ink token, which is Neutral 900: Neutral 900 on each scores Lc 62.8, 62.9 and 63.2, and white scores Lc 43.
158. **The inverse surface restates every token it needs.** `.newspack-brand-inverse` gives a Cobalt background with white text, a white focus ring and white buttons with Cobalt ink. A token that holds `var()` is computed where it is declared, not where it is read, so a derived token such as `--newspack-ui-color-btn-hover` computed at `:root` keeps the root values inside the inverse block. Every token whose value depends on surface, text, button or focus is therefore restated in the block, in the same oklab recipes. The tokens read by the registry's components were audited into three buckets. Restated: surface and text tokens, focus and halo, the button, brand button and selected sets, mark, the neutral-fill trio, borders, input and field tokens, subtle and sunken surfaces, disabled ink. Inherited unchanged because both sides are literals or already computed from restated tokens: destructive fill and ink, the toast surface, status text and tints, overlay, `currentcolor` borders. Unsupported: status and destructive Alerts, and invalid-field styling. The block is in the `newspack-brand` item, so a site that installs the item gets it. The list of unsupported states is in the item's `docs`, in `mapping.json` and in `gaps.md`. Portal-rendered popups (Select list, Dialog, Sheet) mount outside the inverse section and render on the normal surface.
159. **Links on the inverse surface take the inverse text color.** The brand link and `--newspack-ui-color-brand-text` are Cobalt, which scores Lc 0 on the Cobalt surface, so the inverse block restates `--newspack-ui-color-link` as the inverse text color (white, Lc 95.4). `brand-text` and `btn-brand-text` are white there for the same reason.
160. **APCA gates every brand text and fill pair, in the tests.** `scripts/brand-report.mjs` parses `dist/brand.css`, resolves `var()` and oklab `color-mix` the way a browser does, and scores each pair into `build/brand/report.md`; `test/brand-contrast.test.mjs` (not the build) fails on any miss and on any change to the list of pairs. 61 pairs, all passing. Thresholds: Lc 75 for body text and links, Lc 60 for other text (button ink including hover and pressed, muted text, accent inks, inverse button ink), Lc 45 for large or bold display text, focus rings, the checked mark, h1, the input border, the input focus edge and the Alert icon, and Lc 30 for chart fills and disabled ink. Tightest margins per threshold: the muted Badge ink and the Segmented Control's unselected ink on the inverse surface at Lc 60.3 against 60, charts 2 to 4 at Lc 38.3 to 38.7 against 30, and the inverse input border at Lc 58.4 against 45. The tightest pair overall is the 0.3 margin on those two inks; next come inverse button pressed at Lc 62.5 against 60 and the accent inks at Lc 62.8 to 63.2 against 60, with disabled ink at Lc 38.7 against 30 level with chart 2. Resolution is browser-like: a token resolves where it is declared, the inverse block layers over the computed `:root` values, and `color-mix` with `transparent` interpolates premultiplied (`color-mix(in oklab, #fff 30%, transparent)` is `#ffffff4d`, not gray). A `var()` form the evaluator cannot resolve throws instead of looping. Hover, pressed and disabled states are scored where the brand changes them. The toast, the Select item rows and the active Tab marker, which reads `selected` in place, are scored in the light scope (the marker also in the inverse one), since the toast and the Select popup render through portals under `:root`; the gate does not cover the unsupported states.
161. **Type comes from the Figma Brand frame, with new heading tokens.** Sizes and line heights are from the Design System file, page "Typography", the "Brand" frame: H1 36 to 96px at line height 1 (Compressed Black 900), H2 32 to 64, H3 28 to 48, H4 26 to 42, H5 22 to 32, H6 20 to 24, with H2 to H6 at 400 and 500 in the design. None of the clamps match the kit's `2xl` to `6xl` scale, whose minimums differ, so the build adds `--newspack-ui-brand-h1` to `-h6` size and line-height tokens instead of bending the scale. The H6 tokens are author tokens only: no base rule uses them, and `.newspack-brand-eyebrow` (Inter 600, uppercase, the small size) covers small labels. There is no letter-spacing anywhere, because the Figma styles use 0 tracking. The base rule uses 500 for h2 to h5; 400 is available through the fonts. `--font-heading` is `"American Grotesk"` and `--font-display` is `"American Grotesk Compressed"`, both falling back to Inter in the same stack, so the theme works without the fonts item: the fallback is Inter 500 for subheads and Inter 900, still uppercase, for display. Base rules set h1 and `.font-display` to Cobalt, and h2 to h5 to the text color explicitly, so a heading inside a colored container does not inherit. On the inverse surface h1 and `.font-display` descendants reset to the inverse text color, and the block restates `--newspack-ui-color-brand-text` as white, so an element that is itself inverse and display or h1 resolves to white too: the token restatement covers both the element and its descendants. Full accents (Emerald, Morganite, Amber) carry short or large text only, since their ink scores Lc 62.8 to 63.2; body copy goes on the `-subtle` tints, which the gate checks at Lc 75. Dialog and Sheet titles stay Inter 600: they read `--newspack-ui-font-family-heading`, which the brand leaves at Inter, matching "Inter for UI". Kit headings that set no font-family utility, the flow frame title and the docs table-of-contents heading, take the brand heading face.
162. **American Grotesk ships as a stylesheet file with root-relative URLs, and the files stay out of this repo.** `newspack-brand-fonts` is one `registry:file`, `styles/newspack-brand-fonts.css`, with five `@font-face` rules (Compressed Black 900, Regular 400, Italic 400, Medium 500, Medium Italic 500) pointing at `/fonts/american-grotesk/<file>.woff2`. Registry `css` is a JSON object, so five `@font-face` blocks would have needed duplicate or padded keys; a file avoids relying on how the CLI merges them. The woff2 files are never committed to newspack-workspace, which is public on github.com and not a domain our license lets us serve the fonts from. They live in the product site's repo, which serves them, and a deck site copies the same five files into `public/fonts/american-grotesk/`. Same-origin URLs need no CORS setup. The item's description and `docs` say it is for sites on Automattic domains only and to import it once before the theme. The generated stylesheet is outside the build's no-comment guard, and the build writes no comments into it.
163. **The logo is an inline SVG with official paths and per-variant color hooks.** `newspack-logo` uses the official paths from the brand site's RGB logo suite, with the circle and the N as separate paths in every variant. Variants: `default`, `reversed`, `symbol`, `symbol-reversed`. Color hooks are CSS custom properties with literal fallbacks: `--newspack-logo-mark`, `-n` and `-wordmark` for the default variants, and `--newspack-logo-reversed-mark`, `-n` and `-wordmark` for the reversed ones. A value set for one variant never reaches the other, so an ancestor that recolors the logo cannot break a reversed logo. An empty `title` makes the logo decorative: `aria-hidden="true"` and no `role` or `aria-label`; otherwise it is `role="img"` named by `title`, default "Newspack".
164. **The deck keyboard rules follow the tall slide.** `Deck` takes Arrow keys, Page Up and Down, Space, Home and End on `document`, so no focus is needed. Keys are ignored for modified events, `defaultPrevented`, form fields, `video`, `audio`, `contenteditable`, listboxes, menus, dialogs and Radix popper content, and Space also leaves buttons, links and summaries alone. The current slide is the last whose top is at or above the scroller top. A key move focuses the target slide (`tabIndex={ -1 }`, no outline, no scroll) so the next Tab continues from there; dot clicks do not move focus. Presses during a smooth scroll queue from a pending target slide, which is cleared on `scrollend`, or after 1s where `scrollend` is missing. A quick second press onto a tall slide therefore moves past its overflow by design. Once the scroll settles, a slide taller than the viewport is scrolled through by 0.9 of the viewport at a time before the key moves on, so no content is skipped or stranded. At the first and last slides a key that would leave the deck does nothing, so the end of a tall last slide does not jump back to its top. Under `prefers-reduced-motion` the smooth scroll is off. Slides take an `id`, which is encoded in the hash, and the hash scrolls to its slide instantly on load.
165. **The dot navigation follows the slide's tone and shows one dot per slide.** `DeckNav` reads the slides from the `Deck` and toggles `newspack-brand-inverse` on itself while the current slide is a Cobalt one, so the dots and their focus ring stay visible on both surfaces. It carries `bg-transparent` so the class flips the tokens without painting a surface; the inverse background and color live in the base layer, so a utility on the same element wins. Each dot is a button named "Go to slide N: title" with `aria-current="step"`, and the nav is hidden in print. A deck of one slide renders one dot, not none, so the deck still shows where it is. Slides added after mount get no dot, and wheel and touch scrolling do not update the hash; both are accepted.
166. **Slide layouts: Cobalt opening and closing, and clearspace equals the logo height.** `deck-layouts` ships `OpeningSlide`, `ClosingSlide`, `StatementSlide`, `ImageTextSlide`, `StatsSlide`, `QuoteSlide` and `LogosSlide`, built only from theme tokens and the kit's Card. The opening and closing slides are full Cobalt on the inverse surface with the reversed logo, small on the opening slide; the closing slide is only the logo, large and centered. The brand site's clearspace rule asks for space equal to the logo height around it, so each wraps the logo in padding equal to its rendered height: the closing logo and its padding share `clamp(4rem, 10vw, 10rem)`. The closing slide's `title` (default "Newspack") is only its accessible name, and the logo is decorative there so it is not announced twice. The layouts import `@/components/brand/newspack-logo` and `@/components/ui/*`, matching where the registry installs them. They are examples to copy.

## Blue sections

167. **Blue is a per-section mode, not a page theme.** Brand pages are always light: they set `DARK_MODE = false`, have no theme toggle and no theme head script, and never follow `prefers-color-scheme`. An author makes a section or slide blue with `.newspack-brand-inverse` or `.dark`, which are equivalent. The brand item's `.dark` block therefore holds the Cobalt values instead of Neutral's dark palette, so a scoped `.dark` keeps the `dark:` variant (`&:where(.dark, .dark *)`) working inside the section. The block redefines no palette step (`--newspack-ui-color-neutral-0` stays white and `primary-60` stays Cobalt, which the values point at), and Neutral's `.dark [data-slot="select-content"]` and `dialog-content` raises are still dropped. Nothing in the item assumes `.dark` is on `html`: the base rule that paints the Cobalt background and white text selects `.dark, .newspack-brand-inverse`, `color-scheme: dark` is set on the section itself, and every derived token is restated in the block. Portal-rendered popups mount under `body`, outside the section, so they stay light (158). Supersedes 155.
168. **`.dark` and `.newspack-brand-inverse` share one set of values.** `blueTokens` in `scripts/brand.mjs` (the old inverse set, extended) is written to both selectors, in `brand.css` and in the registry item, as are the base paint and heading rules. The tests check the two blocks are identical and resolve the same. The set includes `color-scheme: dark`, since Cobalt is a dark surface. A light section inside a blue one would need every light value restated and was not built.
169. **A blue section restates every shadcn variable.** `--background`, `--foreground` and the rest are literal oklch values at `:root`, so a stock shadcn component inside the section would otherwise stay light. The block takes the token each variable points at in Neutral's `.dark` block (read from the compiled Neutral item, so the two stay in step), with `--primary` and `--sidebar-primary` pointing at the white button fill and its Cobalt ink, and the blue chart series. As in Neutral, the values live in `css['.dark']`, and the item has no `cssVars.dark`.
170. **Status, destructive and invalid states on Cobalt.** Alert text is the surface text color, white on Cobalt, so the status fills are dark palette steps rather than the light tints: success-600 (`#007017`), warning-600 (`#755100`) and error-700 (`#8a2424`), with white text at Lc 85.9, 89.5 and 93.8. Mixing the status colors into Cobalt was tried and dropped: every mix reads as a shade of blue or violet, not as a status. The icons are the 050 steps (Lc 62.6, 73.2, 69.7 on their fills), the Badge text the 000 steps (Lc 80.3, 85.2, 85.7) and the borders the icon color at 50%. `--newspack-ui-color-error` is error-050 (`#facfd2`), so the invalid edge and ring score Lc 67.4 on the field and 71.2 on Cobalt for Checkbox and Radio; error red would score 17.8. Field error messages use error-000 at Lc 87.3. Destructive Alerts share the error fill. The destructive Button keeps Neutral's red fill and white ink (Lc 76.8): the red reads as destructive against Cobalt by hue, and the white default button is the other filled button there. `--newspack-ui-color-destructive-text` points at the error-050 color. Supersedes the unsupported list in 158.
171. **Accents and charts on Cobalt.** The full Emerald, Morganite and Amber fills and their Neutral 900 ink are unchanged (Lc 62.8 to 63.2), and the fills score Lc 51 against Cobalt. White body text cannot sit on the light `-subtle` tints, so a blue section redefines them as the accent at 25% into Cobalt (`#0067a2`, `#4e5bac`, `#4b6197`), where white text is Lc 84.9 to 85.7. The chart series keep Emerald, Morganite and Amber (Lc 51.2 to 51.5), and replace Cobalt (Lc 0 on Cobalt) with primary-000 (`#dfe7f4`, Lc 79.3) and the primary-300 tint (Lc 25) with primary-200 (`#809ed2`, Lc 36.8). Every blue value is a palette token or an oklab mix of tokens.
172. **A `prefers-contrast: more` boost on Cobalt.** The media block restates four tokens on `.dark` and `.newspack-brand-inverse`, so it applies to the section itself wherever it sits: input border primary-000 (Lc 79.3, against 58.4 without the boost), hover border white, disabled border the control border, and the disabled fill the 13% neutral fill. The 19% fill Neutral dark uses puts the placeholder at Lc 58.1; the 13% fill gives 62.2.
173. **The APCA gate covers blue sections.** 87 pairs: the 24 light pairs, and 63 pairs in a blue section, scored as a section that inherits the computed `:root` values. They cover every pair the light page checks plus everything the inverse set checked, the site header's current-page underline (`--newspack-ui-color-accent`, white on Cobalt), the status Alert text and icons, the status Badges, the invalid edges and the field error text, the accent and chart pairs on Cobalt, and two high-contrast pairs. The toast and the Select rows render through portals, so they are scored on the light page only. Thresholds are those of 160. Tightest margins: the muted Badge, the Segmented Control's unselected ink and the default Alert icon at Lc 60.3 (the first two against 60), the placeholder on the high-contrast disabled field at 62.2, the white button pressed at 62.5, and chart 5 at 36.8 against 30. No pair fails. Supersedes the pair count in 160.
174. **What a blue section does not cover.** Portal-rendered popups opened from it render on the light surface. Tokens no kit component reads keep their light values: `--newspack-ui-chart-0` to `-7` (brand charts use `--chart-1` to `--chart-5`), `--newspack-ui-color-error-tint-hover` and `-pressed`, `--newspack-ui-color-primary` and `--newspack-ui-color-against-primary`. The list is in the item's `docs`, in `mapping.json` (`brand.unsupported`) and in `gaps.md`; the blue entries are in `brand.blue` and `brand.blueContrast`.
