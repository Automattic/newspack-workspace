# Gaps

What the Newspack-shaped shadcn components do not match, and the values that have no token. The same lists are in `dist/mapping.json` (`gaps` and `noToken`), generated by `pnpm build`.

## Remaining differences

- **Button**: no loading or wide modifiers, no margins; the link variant is an approximation.
- **Input, Textarea**: no currency or one-time-code variants.
- **Label**: no required or optional markers.
- **Checkbox, Radio Group**: Radix renders a button, not a native input; no bordered choice cards.
- **Select**: the open list is a Radix popover (surface, border, elevation 2). newspack-ui shows the operating system list, so they cannot match. Option padding is our choice.
- **Card**: no filled, colored or sized variants.
- **Dialog**: overlay click closes it (Radix), it does not in newspack-ui. Radix focuses the first button, newspack-ui focuses the title. No sheet drag, steps or footer.
- **Alert**: no dismiss button; the title style is ours.
- **Badge**: no dot, pulse or status variants.
- **Tabs**: no scrolling fade, small or stretch variants.
- **Segmented Control**: Radix Toggle Group, which has no content panels; newspack-ui's segmented control can drive panels, here you render the content from the value. The group is `role="radiogroup"` with radio items, where newspack-ui uses pressed buttons (`aria-pressed`) in a plain group; the visible result is equal, screen readers announce a radio group. Arrow keys move and select together (radio behavior), Home and End too, and Tab enters on the selected item only. Selection can never be cleared. No stretch (form control) layout and no `select` fallback on narrow screens. The sliding thumb is placed by a ResizeObserver in the component, where newspack-ui uses a MutationObserver script; the motion tokens are the same.
- **Sonner**: toasts match the newspack-ui snackbar surface, position, width, icons, close button and motion. Success has a type icon here and none in newspack-ui. Every toast has a close button (newspack-ui only on errors) and errors time out after 8 seconds, where newspack-ui keeps them until closed (Sonner sets the duration per toast, so a site can pass `duration: Infinity` to `toast.error`). The action button is ours; newspack-ui snackbars have none. The stack peek, scale and fade are Sonner's own and differ from newspack-ui's by a few pixels. No pinned list: an error does not stay below the stack. Offsets, width and mobile gutters use newspack-ui spacing and width tokens. The enter and reduced-motion rules ship in the item's `css`.
- **Inter**: newspack-ui names the family `Inter` and loads its own files. The theme item installs `@fontsource-variable/inter` (family `Inter Variable`), so every family stack names both. Same face, different files.
- **Radius**: `rounded-xs` to `rounded-xl` map onto newspack-ui radii (2xs 2px, badge 4px, control 8px, surface 12px, sheet 16px). `rounded-2xl` to `rounded-4xl` have no newspack-ui equivalent and keep Tailwind's values. `--radius` is the surface radius and nothing derives from it. A site that already had `rounded-*` utilities sees them change on purpose.
- **Existing theme entries**: the shadcn CLI never replaces an existing `@theme inline` entry, and `add` re-adds the stock font and radius lines of the project's base. After `init`, delete `--font-sans`, `--font-heading`, `--radius-*` and the Geist import, then install the theme item before the components. A project with no `init` needs one command.
- **Base UI projects**: the CLI rewrites the components' `asChild` to Base UI's `render` prop when the project base is Base UI, and the result does not type-check. Use `init --base radix`.
- **Existing files**: `--yes` alone stops at an interactive overwrite prompt for each existing file (`button`, `alert`). Pass `--overwrite`. Item names stay standard on purpose, since they replace the stock components.
- **`dark:` variant**: the theme appends `@custom-variant dark (&:where(.dark, .dark *))`. The `init` stock `(&:is(.dark *))` stays above it, and the later one wins, so `.dark` on `html` works.
- **Theme utilities**: no `bg-newspack-ui-*` color utilities are generated. Components use `bg-(--newspack-ui-color-x)`; a site can do the same.
- **Chart colors**: from the Insights series palette. The three light oranges (#9a3412, #c2410c, #ea580c) have no `newspack-colors` token. In dark, series 0 to 2 are primary-100 to 300, series 3 to 5 are quaternary-500 to 700, and series 6 and 7 are dark grays.
- **Dark mode**: the `.dark` block, the dark chart series and the modal and dropdown surface steps come from the dark palette; `dark-palette/generate.mjs` writes `dark-tokens.json`, `dark-scales.json` and `dark.css` to `build/dark-palette/`, and `scripts/dark.mjs` reads them from there. The palette lives in this package, not in newspack-ui, for now. A theme's own brand color is not adapted.

## Brand theme

Tokens the brand adds that newspack-ui has no equivalent for. They exist in `scripts/brand.mjs` and the `brand` section of `dist/mapping.json`, not in newspack-ui.

- **Link**: `--newspack-ui-color-link`. newspack-ui links use the text or brand text color directly. Neutral sets the token to `var(--newspack-ui-color-text)`.
- **Accents**: `--newspack-ui-color-brand-accent-{emerald,morganite,amber}` with `-ink` and `-subtle`. newspack-ui has no secondary, tertiary or quaternary CSS tokens, so the fills are the newspack-colors values as literals. They are for backgrounds, shapes and charts, never for text or actions.
- **Blue sections**: the `.dark` and `.newspack-brand-inverse` blocks, one set of values for a Cobalt section with white text, a white focus ring and white buttons. newspack-ui has no Cobalt surface, and Neutral's dark palette is not used.
- **Display font**: `--font-display`, American Grotesk Compressed Black. newspack-ui has no display face.
- **Brand heading sizes**: `--newspack-ui-brand-h1` to `-h6` size and line-height, from the Figma Brand frame. They do not match the `2xl` to `6xl` scale.
- **Chart colors**: `--chart-1` to `--chart-5` are literal brand colors in light, and palette tokens in a blue section. Neutral's `--newspack-ui-chart-0` to `-7` keep their light values in both modes.

Not covered in a blue section: portal-rendered popups (Select list, Dialog, Sheet, toasts) mount under `body`, outside the section, so one opened from a blue section renders on the light surface. Tokens no kit component reads keep their light values (`--newspack-ui-chart-0` to `-7`, `--newspack-ui-color-error-tint-hover` and `-pressed`, `--newspack-ui-color-primary` and `--newspack-ui-color-against-primary`).

## Values with no token

See `noToken` in `scripts/mapping.mjs`: elevation shapes (compiled from the SCSS mixin), focus edge widths, button press scale, size multipliers, checkbox radius and tick, radio dot, select caret padding, badge letter spacing, alert icon margin, tab indicator width, the 600px sheet breakpoint, dialog open scale and title minimum.
